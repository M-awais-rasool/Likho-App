# Likho sound + haptics system

Every sound, vibration and "juice" moment in the app, why it exists, and how to change it.
Code: `lib/feedback/` (engine + meaning → sound/haptic map), sounds: `assets/sfx/`
(generated by `tool/sound_design/generate_sfx.dart`).

## What we learned from the leading apps

| Principle | Where it comes from | How Likho applies it |
|---|---|---|
| **Immediate** feedback (< 100 ms), in sync with the animation | kids' app guidelines; Apple's audio-haptic "harmony" | sounds fire on the state change itself; timelines (splash, level complete) are keyed to the exact animation frames |
| **Causality**: the sound is what the action would sound like | Apple WWDC19 "Designing audio-haptic experiences" | pencil scribble when writing, paper swish on page turns, a pop when a balloon pops, a thump when Pencil lands |
| **Musical family**: rewards are short, bright, rising, consonant | Duolingo's correct chime is two rising notes of a major chord; a major third reads as "happy" to almost everyone | every tonal sound is in **D major pentatonic** (D E F# A B), so overlaps never clash; success always rises |
| **Mistakes are not punished** | kids' UX guidance: "a gentle *Try again* with a shake beats a red X and an error sound children learn to fear" | the wrong sound is two soft wooden notes stepping down, 3.5 dB quieter than success; the haptic is two soft nudges, never the error buzz |
| **Escalation** keeps a run exciting | Duolingo combos, match-3 games | the correct chime climbs one note per right answer in a row (5 steps); order tiles and spelled letters climb the scale |
| **Utility / restraint**: feedback only where it adds meaning | Apple HIG, Android haptics principles ("correlate strength to importance and frequency", avoid buzzy vibration) | frequent taps get the quietest sounds and no vibration; haptics are reserved for answers, landings and rewards |
| **Layered celebrations** ("juice": flash, particles, squash, sound) | *Juice it or lose it* (Jonasson & Purho) | Level Complete: ta-da → star drops with flash + sparkle burst + rising bell + bump → confetti poppers → coin → perfect-score flourish + light rays |
| **Sonic identity**: one recognisable motif | Netflix "ta-dum", Intel chime; sonic-branding practice | the **Likho motif** D - A - D' ("Li-kh-o") plays on the splash, inside Level Complete and at milestones |
| **Consistent loudness**, no harsh highs | UI sound mastering practice (−18…−14 LUFS for taps, a bit louder for notifications; tame 3–6 kHz, cut rumble) | every file is levelled: UI ≈ −27 dB RMS, feedback ≈ −19, celebrations ≈ −17; house EQ cuts < 180 Hz and dips 4.5 kHz; peaks ≤ −1 dBFS |
| **Variation** against fatigue | game audio practice | taps, choices and splash scribbles rotate between 3 variants |
| **User control** | Duolingo has separate sound / haptics switches | Settings → "Sound effects & awaaz" and "Vibration"; "Reduce motion" turns off sparkles, rays and confetti |

Nothing is copied: every sound is synthesised from scratch (no samples, no other app's audio).
Duolingo's success chime is a two-note "dong-ding"; ours is a pencil tick plus a three-note
kalimba/bell arpeggio in our own key and timbres.

## The palette (55 files, 2.9 MB)

Timbres: **bell** (rewards, stars), **kalimba** (progress steps), **soft wood** (UI, gentle
mistakes), **pops** (choices), **paper and pencil noise** (writing, pages), **sparkle** (tiny high
bells + air, the "you earned something" layer).

## Code

```
AppFeedback (lib/feedback/app_feedback.dart)   screens call meanings: fb.correct(streak: 3), fb.star(2)…
  ├─ SoundEngine  (sound_engine.dart)          JustAudioSoundEngine in the app, silent in tests
  └─ HapticsEngine (haptics.dart)              SystemHaptics: platform feedback types, short rhythms
GameFeedback (game_feedback.dart)              listens to the level's rules (LevelSession), so the
                                               gameplay screen needs no changes
FeedbackCue(at: .75, play: (f) => f.star(1))   declarative timeline for animated screens
```

* `AppFeedback.of(context)` from any widget; buttons use `withSound(context, ButtonSound.press, onTap)`.
* `main()` installs the real engines and preloads `Sfx.warm` (splash + answer sounds).
* Effects never take the audio session: they mix with Pencil's voice and the TTS prompts and do
  not pause other apps' audio.
* Latency: just_audio with preloaded players and small buffers. If device testing shows lag on
  low-end Android, implement `SoundEngine` with a game audio engine (e.g. flutter_soloud); nothing
  else changes.

## Changing a sound

Edit its recipe in `tool/sound_design/generate_sfx.dart` (all recipes are in `palette()`), run
`dart run tool/sound_design/generate_sfx.dart`, and listen. A recorded replacement can simply be
dropped in as `assets/sfx/<name>.wav` (keep it short, levelled like its neighbours, starting
without silence).
